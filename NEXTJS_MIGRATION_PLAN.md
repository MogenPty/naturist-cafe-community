# Migration Plan: Vite → Next.js

## Current State Analysis

### ✅ What Works Well (Keep As-Is)
- **Component Architecture**: All React components are well-structured and mostly independent
- **Styling**: Tailwind CSS v4 + custom CSS works fine, minimal Vite-specific patterns
- **No Vite-Specific Features**: No use of `import.meta.env`, dynamic imports, or Vite-only APIs
- **Component Types**: All components are client-side (use `useState`, `useEffect`) - will need `'use client'` in Next.js
- **Static Assets**: Cloudinary integration is framework-agnostic, assets in `public/` will work as-is
- **Custom CSS**: All utilities in `index.css` are plain CSS, will work in Next.js

### ⚠️ Current Setup
- **Framework**: Vite + React 19 + TypeScript
- **Routing**: Manual scroll-based SPA (no React Router)
- **Structure**: Single page with 6 sections (Hero, Constitution, Markets&Walks, Board, Join, Login)
- **Build Output**: `dist/` folder with static files
- **Entry Point**: `index.html` → `main.tsx` → `App.tsx` → sections
- **Next.js Already Installed**: `@next` in node_modules, env vars configured (`.env.local` has `NEXT_PUBLIC_*`, `NEXTAUTH_*`)

## Migration Strategy

### **Approach: Single-Page App in Next.js (App Router)**
Since your site is a scrolling SPA, convert to Next.js but **keep the single-page UX**:
- `app/page.tsx` = current `App.tsx` (with all sections)
- Components stay in `src/components/` (or move to `app/components/`)
- Add `'use client'` to all interactive components
- Keep custom CSS as global styles
- Keep `public/` assets as-is

## Step-by-Step Migration Plan

### **Phase 1: Install & Setup Next.js**
1. Ensure Next.js dependencies:
   ```bash
   pnpm add next@latest react@latest react-dom@latest
   ```
   (Already installed per `node_modules/@next/`)

2. Create `next.config.js` (or `next.config.ts`):
   ```javascript
   /** @type {import('next').NextConfig} */
   const nextConfig = {
     reactStrictMode: true,
     // Required for Cloudinary domain
     images: {
       remotePatterns: [
         {
           protocol: 'https',
           hostname: 'res.cloudinary.com',
         },
       ],
     },
   };
   module.exports = nextConfig;
   ```

3. Create `next-env.d.ts` (auto-generated by Next.js on first build, but can create manually):
   ```typescript
   /// <reference types="next" />
   /// <reference types="next/image-types/global" />
   ```

4. Add TypeScript config for Next.js (already have `tsconfig.app.json`, may need minor tweaks)

### **Phase 2: Restructure Project Layout**

**Option A: App Router (Recommended)**
```
.
├── app/
│   ├── layout.tsx      (global layout + CSS imports)
│   ├── page.tsx        (your current App.tsx content)
│   └── globals.css     (your current src/index.css)
├── src/components/     (keep existing, or move to app/components/)
├── public/             (keep existing assets)
├── .env.local          (already has NEXT_PUBLIC_* vars)
└── package.json
```

**Option B: Pages Router (Legacy)**

│   ├── _app.tsx        (wraps all pages, includes AgeGate)
│   └── index.tsx       (your current App.tsx)
├── public/
└── src/components/

**Recommendation**: Use **App Router** for modern Next.js features.

## Potential Issues & Solutions

### 1. **Client/Server Component Boundaries**
- **Issue**: Next.js treats all components as server components by default. Your components use `useState`, `useEffect`, browser APIs (`document`, `window`, `sessionStorage`).
- **Fix**: Add `'use client'` directive to any component using hooks or browser APIs. See Phase 3.

### 2. **Routing Changes**
- **Issue**: Current navigation uses `document.getElementById()` for smooth scroll.
- **Fix**: This still works in Next.js! Keep it. Alternatively, use Next.js `next/link` for navigation if converting to multi-page, but for SPA scrolling, `scrollIntoView` is fine.

### 3. **Asset Paths**
- **Issue**: Vite may have used `/` root-relative paths. Next.js also serves from root for `public/`.
- **Fix**: Static assets in `public/` will be accessible at same paths. Cloudinary URLs unaffected.

### 4. **CSS Import Paths**
- **Issue**: Components may have `import "./index.css"` or similar.
- **Fix**: In Next.js, global CSS can only be imported in `app/layout.tsx` or `pages/_app.tsx`. Move all global CSS imports there. Component-specific CSS modules would use `import styles from './Component.module.css'` (but you're using Tailwind + global utilities, so likely no changes).

### 5. **TypeScript Configuration**
- **Issue**: Next.js has specific TypeScript requirements.
- **Fix**: Next.js will auto-generate `next-env.d.ts`. Ensure `tsconfig.json` includes `"types": ["next"]` if needed. Keep existing configs but verify with `pnpm dev`.

### 6. **Build Differences**
- **Issue**: `tsc -b` build step in Vite may need adjustment.
- **Fix**: Next.js runs its own tsc implicitly. Remove custom `tsc -b` from scripts.
